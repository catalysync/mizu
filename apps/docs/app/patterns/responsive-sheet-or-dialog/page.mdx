# Responsive sheet or dialog

A recipe for showing the same content as a centered dialog on wide screens and as a bottom sheet on narrow ones. It is composed from `Modal`, `Sheet` and `useMediaQuery`; there is no separate component.

## Recipe

Keep one `ResponsiveDialog` that owns the open state, the trigger and the content. It picks `ModalContent` or `SheetContent` from a media query. Both parts sit under one Radix root, so the dialog stays open when the viewport crosses the breakpoint.

```tsx
import {
  Button,
  Modal,
  ModalBody,
  ModalContent,
  ModalDescription,
  ModalFooter,
  ModalHeader,
  ModalTitle,
  ModalTrigger,
  SheetBody,
  SheetContent,
  SheetDescription,
  SheetHeader,
  SheetTitle,
  useMediaQuery,
} from '@mizunagara/react';

// Media queries cannot read CSS custom properties, so the breakpoint is a literal.
const NARROW_QUERY = '(max-width: 640px)';

export function ResponsiveDialog({
  open,
  onOpenChange,
  title,
  description,
  trigger,
  children,
  footer,
}) {
  const isNarrow = useMediaQuery(NARROW_QUERY);

  // Modal and Sheet are both aliases of Radix Dialog.Root. Sharing one root keeps
  // `open` stable when the viewport crosses the breakpoint; only the content swaps.
  return (
    <Modal open={open} onOpenChange={onOpenChange}>
      {trigger && <ModalTrigger asChild>{trigger}</ModalTrigger>}
      {isNarrow ? (
        <SheetContent side="bottom">
          <SheetHeader>
            <SheetTitle>{title}</SheetTitle>
            {description && <SheetDescription>{description}</SheetDescription>}
          </SheetHeader>
          <SheetBody>{children}</SheetBody>
          {/* ModalFooter is the shared footer styling; sheets have no footer part of their own. */}
          {footer && <ModalFooter>{footer}</ModalFooter>}
        </SheetContent>
      ) : (
        <ModalContent size="md">
          <ModalHeader>
            <ModalTitle>{title}</ModalTitle>
            {description && <ModalDescription>{description}</ModalDescription>}
          </ModalHeader>
          <ModalBody>{children}</ModalBody>
          {footer && <ModalFooter>{footer}</ModalFooter>}
        </ModalContent>
      )}
    </Modal>
  );
}
```

Use it like any dialog. The caller keeps `open` in state, and passes the trigger as a prop so Radix can return focus to it on close:

```tsx
const [open, setOpen] = useState(false);

<ResponsiveDialog
  open={open}
  onOpenChange={setOpen}
  title="Edit profile"
  description="Changes apply to your account immediately."
  trigger={<Button>Edit profile</Button>}
  footer={
    <>
      <Button variant="ghost" onClick={() => setOpen(false)}>
        Cancel
      </Button>
      <Button variant="primary" onClick={() => setOpen(false)}>
        Save
      </Button>
    </>
  }
>
  <p>Form fields go here.</p>
</ResponsiveDialog>;
```

## Choosing the breakpoint

`640px` is a starting point. Pick the width where a centered dialog stops fitting your content, and change `NARROW_QUERY` in one place.

## Guidelines

**Do:**

- Keep the content in one `ResponsiveDialog`. Two copies drift apart.
- Keep the primary action in `footer`. On a sheet it sits at the bottom of the screen, within thumb reach.
- Keep the body short. The sheet body scrolls; the footer stays in place.

**Don't:**

- Don't render both branches at once or hide one with CSS. Both would mount, and two focus traps would fight.
- Don't open a second dialog from inside this one. Nested dialogs are not supported (see [Modal](/components/modal)).
- Don't put a full multi-step form here. Use a page instead.

## Accessibility

- Both branches are Radix dialogs. Focus is trapped while open, Escape closes the dialog, and focus returns to the trigger when it is passed as the `trigger` prop.
- `ModalTitle` and `SheetTitle` supply the accessible name. Always pass a `title`.
- If the viewport crosses the breakpoint while the dialog is open, the dialog stays open but its content remounts. Focus then lands on the first focusable element in the dialog, which may not be the one the user had selected.
