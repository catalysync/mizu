## P01 Satisfiable peers

- Change: every internal `@mizunagara/*` peer range moved from `>=0.2.0` to `>=0.1.0`, which the
  current 0.1.0 versions satisfy and the 0.2.0 release also satisfies. Do not use `^0.1.0`: once css and tokens
  bump to 0.2.0, changesets treats the out-of-range peer as breaking and bumps every dependent to 1.0.0
  (seen in `changeset status --output`). `>=0.1.0` keeps the release at 0.2.0 with minor bumps.
- Check 1: `node scripts/release/packages.mjs --check`

  - After: exit 0.
- Check 2: `pnpm pack` in all nine publishable packages, then `npm i --prefer-offline` of the packed
  `tokens`, `css`, `tailwind-preset` and `react` tarballs in a clean temp dir.
  - Result: `added 74 packages`, no `npm warn` lines, `npm ls` shows no invalid or missing peers.
  - Note: the packs `charts`, `finance`, `commerce`, `query-builder` and `advanced-query-builder` have no
    `dist` yet, because they are not built. Their tarballs are metadata only. Build gating comes in P03 and P08.
- Status: done.

## P02 CJS types wired

- Change: `@mizunagara/react` `exports["."]` now nests the types under each condition:
  `import: { types: ./dist/index.d.ts, default: ./dist/index.js }` and
  `require: { types: ./dist/index.d.cts, default: ./dist/index.cjs }`.
  The top-level `types` field stays for node10.

  - Before: node10 ok, node16 CJS "Masquerading as ESM" (FalseESM), node16 ESM ok, bundler ok.
  - After: node10, node16 (CJS), node16 (ESM), bundler all green. "No problems found".
- Status: done.

## P03 Export-shape gate

- Change: new `scripts/check-exports.mjs`. For each publishable package (or the directories given) it runs
  `pnpm pack`, then `publint run <tgz> --level warning --strict` and `attw <tgz>`. It exits 1 on any failure.
  `packages/react/scripts/validate-build.mjs` replaces its file-exists block with a call to this gate.
  Root script `validate` runs it. The gate needs a build first; it does not build.
- attw exclusions (documented in the script): tokens `css json ts rn`, commerce `css`, finance `css themes/*`.
  These are CSS or JSON data, or TypeScript sources that Node cannot load. publint still checks that each exists.
  Owner decision for later: tokens `./ts` and `./rn` are ESM TypeScript sources. Node cannot require them.
- Gate caught a real bug: `tailwind-preset` `./legacy` pointed at `legacy-preset.js`, which is CJS in a
  `type: module` package. Renamed to `legacy-preset.cjs` (the import path is unchanged, so consumers are not affected).
- Tooling: `publint` 0.3.25 added as a root devDependency. The gate itself was tested as described below.
- Check 1: `pnpm build` for the nine packages, then `pnpm validate`
  - Result: `ok` for publint and attw on all nine packages, `check-exports: 9 package(s) ok`, exit 0.
- Check 2 (fixture): temporarily set `packages/react` `types` (and the import `types`) to `./dist/missing.d.ts`,
  then `node scripts/check-exports.mjs packages/react`
  - Result: `FAIL packages/react publint` and `FAIL packages/react attw`, exit 1. The manifest was restored from git afterwards.
- Gotcha fixed during the work: the first version reused one temp dir, so every package was checked against the first tarball. Each pack now has its own dir.
- Status: done.

## P05 Build fails on unresolved tokens

- Change: `packages/css/build.mjs` ends with `checkTokens()`. It scans every built CSS file and the tokens
  `variables.css` (resolved via `@mizunagara/tokens/css`). A `var(--mizu-*)` with no definition anywhere
  fails the build, unless the reference carries an explicit fallback in `var()`. Those are the documented
  fallback set: the layout gaps and `--mizu-app-layout-sidebar-width`, 11 names in all.
  The check lives in the css build, as the plan asks. The tokens config is unchanged.
- Baseline: `pnpm --filter @mizunagara/css build` exits 0.
- Fixture 1 (token removed from source, as the plan describes): remove `surface.default` from
  `packages/tokens/src/semantic/colors.json`, then `pnpm --filter @mizunagara/tokens build`.
  The tokens build itself fails with style-dictionary's `Reference Errors` (the `surface.primary` alias
  points at it), so `pnpm build` exits non-zero before css runs.
- Fixture 2 (gate itself): remove `surface.default` and its alias `surface.primary`, so tokens builds.
  `pnpm --filter @mizunagara/css build` exits 1 with `unresolved token --mizu-surface-primary (no definition, no fallback)`
  and the same for `--mizu-surface-default` in `dialog.css` and others.
- Restored from git after both fixtures; baseline css build exit 0 again.
- Status: done. Note for C03 and C05 later: `dialog.css` and the accordion and alert files still rely on bare
  `surface-default` and `surface-primary`. They will fail this gate if those tokens are ever dropped.

## P10 Tree-shaking gate

- Change: new `packages/react/scripts/check-treeshake.mjs [subpath]`, default `button`. It bundles the component's
  source entry with esbuild (react, radix and other bare imports external), reads the metafile, and fails if any other
  `src/components/<Dir>` contributes bytes (`bytesInOutput > 0`) or the minified bundle exceeds 4096 bytes.
  esbuild comes from tsup's dependency path, so no new dependency was added. `validate-build.mjs` runs the gate for `button`.
- Why source, not dist: tsup's dist comments do not reliably mark component files, and the chunks are opaque to the
  metafile. The source entry gives the same per-module answer a consumer's bundler reaches.
- Check: `node packages/react/scripts/check-treeshake.mjs button`
  - Result: `component sources in output: Button`, minified 1841 bytes (budget 4096), `check-treeshake: ok`, exit 0.
  - Also `alert-dialog` passes (1522 bytes).
- Negative check: `export { Modal } from '../Modal';` appended to `src/components/Button/index.ts`.
  Result: `component sources in output: Button, Modal`, `FAIL foreign component code in bundle: Modal`, exit 1.
  The file was restored from git.
- Status: done.
